# live-commentary

Real-time, **multilingual** sports commentary for *any* match. Plug in a data
feed, pick a language, and the system narrates the game as it happens — in the
voice of a broadcaster, generated by Claude.

It works on two layers so it's both **real** and **runnable right now**:

- **Live + Claude** — pull genuine play-by-play from a provider (ESPN works
  with no API key) and let Claude write natural, idiomatic commentary in any
  language. Optionally speak it aloud.
- **Offline fallback** — a scripted match and a rule-based engine mean the
  whole pipeline runs with **zero setup, zero keys, zero network**. Great for
  demos and CI.

```
[ Provider ] --events--> [ Runner: dedup + history ] --> [ Engine ] --> text --> [ Speaker ]
  ESPN / football-data /                                  Claude (any language)      gTTS /
  simulated / your own                                    or offline templates       pyttsx3
```

## Quickstart (no setup)

```bash
git clone <this-repo> && cd live-commentary
python -m livecommentary demo                 # offline scripted match, English
python -m livecommentary demo --language Spanish
python -m livecommentary demo --style hype --speed 6
```

`demo` needs nothing installed — it runs on the standard library alone.

## Go real

```bash
pip install -e ".[live,claude]"        # requests + anthropic
export ANTHROPIC_API_KEY=sk-ant-...    # enables Claude, in ANY language

# What's on right now? (ESPN, no key needed)
python -m livecommentary discover --provider espn --sport soccer --league eng.1

# Commentate a live match in Japanese, hype style, spoken aloud
python -m livecommentary live \
    --provider espn --sport soccer --league eng.1 \
    --match 704123 --language Japanese --style hype --speak
```

When `ANTHROPIC_API_KEY` is set, commentary is generated by Claude directly in
your chosen language (idiomatic, not word-for-word). Without it, the offline
template engine takes over automatically so nothing breaks.

### Common ESPN slugs

| sport        | league               |
|--------------|----------------------|
| `soccer`     | `eng.1`, `usa.1`, `esp.1`, `uefa.champions` |
| `basketball` | `nba`, `wnba`, `mens-college-basketball` |
| `football`   | `nfl`, `college-football` |
| `baseball`   | `mlb`                |
| `hockey`     | `nhl`                |

Find a live `--match` id with the `discover` command above.

## Languages

Pass any language by name to `--language` (e.g. `English`, `Spanish`, `French`,
`Japanese`, `Arabic`, `Portuguese`, `Hindi`, `Mandarin`). The Claude engine
writes natively in that language. The offline engine ships canned phrasing for
English, Spanish, and French and falls back to English otherwise. Spoken output
maps the language to the right TTS voice automatically.

## Commentator styles

`--style` selects a persona: `play-by-play` (default), `analyst`, `hype`,
`radio`, `calm`. Add your own in `livecommentary/styles.py`.

## Speak it aloud

```bash
pip install -e ".[voice]"      # gTTS (online) and/or pyttsx3 (offline)
python -m livecommentary demo --speak --language French
```

If no TTS backend is available, the system stays silent and keeps printing.

## Add a new provider (this is the whole point)

A provider is the only thing you write to support a new sport or feed.
Implement two methods and the rest — dedup, language, voice, the loop — comes
free:

```python
from livecommentary.providers.base import MatchProvider
from livecommentary.models import MatchState, MatchEvent, Team, EventType

class MyProvider(MatchProvider):
    name = "myfeed"

    def get_state(self, match_id) -> MatchState:
        ...  # return current score / clock / status

    def get_events(self, match_id) -> list[MatchEvent]:
        ...  # return all events so far, each with a STABLE id for dedup
```

Register it in `livecommentary/providers/__init__.py` and it's available as
`--provider myfeed`.

## Use it as a library

```python
from livecommentary.providers.simulated import SimulatedProvider
from livecommentary.engine import TemplateEngine   # or ClaudeEngine
from livecommentary.runner import Runner

Runner(SimulatedProvider(speed=8), TemplateEngine("French")).run("sim-1")
```

See `examples/demo.py`.

python -m unittest discover -s tests -v

## Layout

```
livecommentary/
  models.py          normalized Team / MatchEvent / MatchState
  providers/
    base.py          the provider interface
    espn.py          real, key-less live feed (soccer + US sports)
    football_data.py real, key-based soccer feed
    simulated.py     offline scripted match
  engine.py          ClaudeEngine (Claude) + TemplateEngine (offline)
  styles.py          commentator personas
  tts.py             optional speech (gTTS / pyttsx3)
  runner.py          polling loop, dedup, history, output
  cli.py             demo / live / discover commands
```

## Notes & limits

- ESPN's endpoints are public but undocumented; parsing is defensive and may
  need tweaks if their schema changes.
- Respect each data provider's terms of use and rate limits.
- Commentary quality scales with the model; `claude-3-5-haiku-latest` keeps up
  with live pace cheaply, larger models read richer.
